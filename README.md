# 防汛需求与道路情景覆盖数据分析平台

预案分析员在暴雨情景下比较居民在不同出发时刻，能否沿**可通行道路**到达**既有安置点**，
并区分覆盖面变化究竟来自**道路恢复、人口资料变化还是分析边界改变**。

平台只计算**可达人口及证据限制**，不做安置点选址、人员分配或物资调运。

在冻结的道路时态与场所开放区间之上，平台另提供**安置点实体解析与容量证据核验**：
把公告、场所主档、坐标修订、开放/撤销记录、容量单位和核验时点关联成**带来源的场所实体**，
逐个场所计算情景时点的**可用容量区间**与证据状态，并与**可达网格需求分开展示**。
这一模块同样**不分配居民、不确定网格→场所先后次序、不逐格扣减容量**，也不把未分配容量
推算成已服务人数；场所容量短缺**不会**被用来排除任何网格。

技术栈：**React 18 + TypeScript + Vite + Leaflet（离线 Simple CRS 平面地图）**、
**FastAPI**、**PostgreSQL 18**、**Redis 8（失效通知/任务状态，可选降级）**。

```bash
docker compose up --build
```

| --- | --- | --- |
| 前端 | http://localhost:8080 | Nginx 托管静态资源并反代 `/api` |
| 后端 API | http://localhost:8000 | 交互式文档 http://localhost:8000/docs |

## 3. 数据与口径说明

### 3.1 来源目录（全部带原文、单位、发生/登记时间、修订号与证据截止点）

- 规则网格人口（含修订表与基准日）、路网节点、**有向边修订**、安置点及开放区间、
  封路/分时限速事件（**追加式多修订行** + 修订审计）、区域边界；
- 每个网格保存与路网的**连接位置与互斥分配比例**；多出口网格按互斥子份额切分人口；
- 事件每次修订只追加新行（含 `received_at`），快照按截止点取该事件最新的**可见**修订；
  因此旧截止点分析在新修订录入后仍可精确复现，不会被原地 UPDATE 改写历史。

### 3.2 情景工作区固定四项输入

人口基准日、出发时刻、允许行程时长、道路资料截止点（另可选分析边界）。
四要素 + 路网版本 + 边界共同组成**完整情景签名**，作为缓存唯一键。

### 3.3 时变路网求解规则（`app/engine/traversal.py`）

1. 遍历边时检查**整条通行时段** `[进入, 离开)` 是否与封路区间相交，而非只看出发时刻；
2. 分时限速按覆盖整段的最严格限速计算（定点细化）；
3. 仅 `allow_wait` 节点可等待道路恢复，等待段与等待成本逐段记录；
4. 等待后到达仍超出总时限的标签被剪枝，**不计入覆盖**；
5. 安置点按**实际到达时刻**判断开放；到达时关闭且节点允许等待，可等到下一开放区间起点，
   等待同样计入总时长；
6. 每个标签携带见证路径（节点序列 + 边序列 + 等待段）。

### 3.4 覆盖、去重与未知边界

- 份额人口 = 网格人口 × 互斥比例；同一份额能到多个安置点只计一次（取最早实际到达）；
- 网格级汇总天然去重，同一网格人口绝不重复计数；
- 未知单列且不默认全覆盖或零需求：
  `unknown_no_connector`（无连接）、`unknown_allocation_gap`（比例缺口）、
  `unknown_ratio_over_one`（比例矛盾）、`unknown_connector_missing`（连接节点不在该路网版本）。

### 3.5 混合计算与缓存纪律

- 常规出发窗口**预计算**；临时封路/限速登记后立即参与后续**即时计算**；
- 每项结果标注**证据截止时间**；不同出发时刻/开放条件签名不同，缓存命中也不复用他者覆盖面；
- 封路修订沿 `task_edge_dependencies` 定位受影响任务，并显式筛查**恢复候选**
  （路网含该边但旧路径未经过的任务——重开可能恢复此前不可达区域）；
- 同截止点迟到修订物化为**新路网版本**（新指纹、新 version_id、新签名），
  旧任务物理上无法覆盖新版本缓存行；重建期间的路网更新只会再产生新版本。

### 3.6 对比报告的共同分母

- 仅在两侧共有的网格集合上计算覆盖率与变化；
- 道路/开放窗口效应、人口修订效应、分析边界增删、未知份额变化**分桶展示**；
- 人口或边界口径不一致时给出显式警告，不能把换了分母的覆盖率当作改善；
- 发布记录（`publications`）固化两侧完整输入清单（修订号、截止点、版本指纹、网格人口与边界）。

### 3.7 安置点实体解析与容量证据核验（独立职责模块）

在不改变冻结道路时态与场所开放区间的前提下，新增五条**各自持有版本流**的职责
（`shelter_module_versions`）：

| 模块 | 版本键 | 职责 |
| --- | --- | --- |
| `catalog` 场所目录 | 可见主档 + 坐标修订的内容指纹 | 主档、坐标修订（追加式）按截止点物化 |
| `announcements` 公告接入 | 每条公告最新可见修订的指纹 | 开放/容量/撤销/坐标公告，`received_at` 控制可见性 |
| `entity_resolution` 实体消歧 | 目录×公告×人工处置×策略的指纹 | 把公告匹配到唯一场所；歧义/冲突显式待核 |
| `capacity_verification` 容量核验 | 各场所容量状态/单位/区间的指纹 | 逐场所计算可用容量区间与证据状态 |
| `scenario_report` 情景报告 | 报告内容签名 | 需求侧与场所侧并列、比较、迟到公告差异 |

**两种实体解析策略**（`POST /shelter-intel/reports` 的 `policy`）：

- `auto`：唯一候选且证据充分即自动接受；多候选中只有**证据明显领先**（同时命中名称/地址/坐标）
  才接受，其余待人工确认——响应快，但歧义项必须待确认；
- `manual`：只要存在多个候选就保留人工确认——误合并更少，但更多场所暂时不可用。

**证据核验口径**（场所侧独立指标 `capacity_low/high`，单位统一到“人”）：

- 容量单位：`人` 直接采用；`床位` 按 **1 床 = 1 人** 应急安置口径换算；`房间` 缺每间人数时
  **无法换算 → 容量未知**（不猜测）；单位无法识别 → 容量未知；
- 现有占用**未知** → 可用容量 `[0, 核验容量]`，状态 **上限不确定**；
- 核验证明**过期** → 容量未知（不沿用旧数字）；
- 情景时点**尚未开放**或已**撤销** → 未开放，可用容量记 0 且不计入总量；
- 实体**待核/冲突/驳回** → 实体待核，不并入任何场所、不计入总量。

**需求侧与场所侧永不混淆**：报告同时给出
`reachable_demand_population`（只读冻结覆盖汇总的网格级去重合计）与
`capacity_low/high_total`（只读场所容量证据），并仅在报告层给出
`capacity_shortfall / capacity_meets_demand_lower_bound / inconclusive_between_bounds`
的**比较**，不决定网格→场所次序、不逐格扣减、不产出“已服务人数”。

**迟到公告纪律**：公告按 `received_at <= 截止点` 取可见修订；迟到补传**只产生新报告**并列出
相对上一版的**受影响场所**，旧报告按内容签名去重、不可改写。

## 4. 小型可手算样例（每条边 1000m / 60km/h = 1 分钟，T0=2026-07-15 08:00 UTC）

- 单向边 `E1(N1→N2)`（无反向边）、绕行 `N2→N5→N6→N4`；
- `EV1`：E3 河东桥 08:05–08:20 临时封闭，N3 不可等待；
- `EV2`：E1 分时限速 20km/h，08:10–08:30（该时段通过需 3 分钟）；
- `EV3`：E7 东站引道 C1 时“尚未恢复”，C2 修订为 08:40 重开；
- 安置点 S1@N3、S2@N6（07–18 点开放），S3@N7（仅 09–12 点开放）；
- 网格：G1 多点重叠、G2 双出口 0.6/0.4、G3 无连接、G4 比例缺口 0.3、
  G5 比例和 1.2、G6 人口修订 1000→1200、G7 属另一边界、G8 仅靠 E7 外接（恢复验证）。

## 5. 已执行的验证与结论

以下验证均在本工作区实际执行通过：

1. **后端单元/集成测试 52 项全部通过**（`pytest`，约 32 秒；33 项冻结基线 + 19 项安置点情报）：
   - 单向边、绕行、整段封路判断（进入时开放但行驶中撞上也判不可行）、分时限速整段生效；
   - 不可等待节点无法等待、等待后超时剪枝、安置点按实际到达时刻开放、见证路径留痕；
   - 多出口互斥份额、多点重叠只计一次、四类未知边界、证据截止标注、边界过滤；
   - 同签名任务复用与引用计数、不同出发时刻绝不共享缓存、查看者释放不取消共享任务；
   - 临时事件即时失效、重开恢复此前不可达网格、旧任务不能覆盖新版本索引、失效窗口重建、
     **旧截止点快照在后续修订录入后仍可精确复现（追加式事件修订回归测试）**；
   - 共同分母对比三因分解、人口修订不计入道路效应、边界变化单列、发布清单完整性；
   - **安置点情报 19 项**：单位归一化与换算（人/床/房间）、床与人混用、占用未知→上限不确定、
     证明过期→容量未知、不可换算单位→容量未知、到达时未开放、同名异址待核、
     `auto`/`manual` 策略差异、迟到撤销只产生新报告并列出受影响场所、
     容量低于需求→shortfall 且网格覆盖不受影响、五条独立版本流、人工确认只影响后续报告、
     坐标修订按截止点可见；
   - FastAPI TestClient 端到端：情景生命周期、缓存命中、下钻、事件失效、比较、发布、预计算，
     以及安置点情报接口（目录/公告/实体/报告/版本/迟到补传/人工确认）。
2. **前端 `npm run build` 通过**（TypeScript 严格模式 + Vite 生产构建，42 个模块），
   新增「场所容量核验」标签页。
3. **真实 HTTP 端到端流程通过**（uvicorn 实跑）：创建情景 → 场所目录/公告 → `auto` 与
   `manual` 两份报告（需求 37977 人 vs 容量 1050–1450 / 750–1150，均 shortfall）→
   补传迟到撤销 → 新截止点报告 M_S4 变为 `revoked` 并列入受影响场所、旧 C1 报告按签名幂等 → 五模块版本齐备。

## 6. 主要 API 一览

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/scenarios` | 按签名创建/复用情景并同步得到覆盖面 |
| GET | `/tasks/{id}/summary` `/grids` `/arrivals` `/witness` | 汇总、份额、节点到达、网格下钻 |
| POST | `/tasks/{id}/release` | 查看者离开（引用计数，不取消他人任务） |
| POST | `/events` | 临时封路/限速登记并即时失效受影响范围 |
| POST | `/cache/precompute` `/cache/rebuild` `/cache/invalidate` | 预计算、重建、按边失效 |
| POST | `/comparisons` | 共同分母对比与三因分解 |
| POST | `/publications` GET `/publications` | 结果发布与完整输入清单 |
| GET | `/sources/*` | 来源原文、事件审计、边修订、安置点、人口连接 |
| GET | `/shelter-intel/catalog` `/announcements` `/entities` `/versions` | 场所目录、可见公告、实体消歧、五模块版本 |
| POST | `/shelter-intel/announcements` | 接入公告（可指定 `received_at` 模拟迟到补传） |
| POST | `/shelter-intel/entities/override` | 人工确认/驳回歧义公告（只影响后续报告） |
| POST | `/shelter-intel/reports` GET `/shelter-intel/reports[/{id}]` | 生成/查询情景报告（需求与容量分列） |
| POST | `/admin/reseed` `/admin/apply-c2-revision` | 样例数据管理 |
